#### [0.4.2](https://github.com/lenzhq/n8n-nodes-lenz/compare/0.4.1...0.4.2)

- Correct the low-depth price location: it lives at `cost_options.verify.depth.low`, not in `costs` under `verify_low`, which does not exist, so the documented division evaluated to NaN (0.4.2)
- Say that low depth also stops the debate after the opening arguments, so a low verdict has no rebuttal round, in every Depth description in the node and the README (0.4.2)
- No behaviour change: every output field is identical to 0.4.1 and the only difference on the wire is the User-Agent version (0.4.2)

#### [0.4.1](https://github.com/lenzhq/n8n-nodes-lenz/compare/0.3.0...0.4.1)

- Expose `depth` on Verify (Deep) and Submit Batch: `low` searches fewer sources, skips the recovery fetch tiers and stops the debate after the opening arguments, for half the credits, 5 against 10 (0.4.0) — wording corrected in 0.4.2
- Let each claim in a batch override the batch-wide depth, so one submission can mix 5- and 10-credit checks (0.4.0)
- Report the depth a verdict was actually produced with, which differs from the depth requested when an existing standard verdict answers a low request (0.4.0)
- Expose `focus` on Extract Claims, refusing an over-long hint before the request is sent rather than truncating it (0.4.0)
- Name a `no_match` extraction in a message, so a focus that excluded every claim is not mistaken for text containing none (0.4.0)
- Label the Assess and batch-item inputs "Claim" instead of "Text", leaving the parameter keys saved in existing workflows unchanged (0.4.1)
- Drop the hardcoded "8-model" pipeline count from the Verify descriptions and the README, since the count has already drifted once (0.4.1)
- Gate publishing on the test suite and on the tag matching package.json, and pin CI to the Node version that publishes (0.4.1)
- Published as 0.4.1: the 0.4.0 bump reached main but was never tagged, so 0.4.0 has no npm release and its changes ship here (0.4.1)

#### [0.3.0](https://github.com/lenzhq/n8n-nodes-lenz/compare/0.2.1...0.3.0)

- Speak the single per-account credit pool that replaced the six per-endpoint quotas (0.3.0)
- Quote `cost` beside `credits_remaining` on an out-of-credits refusal, and carry both on the error output as fields an IF node can read (0.3.0)
- Stop calling the balance a "quota" held "for the current API key": it is per account and shared across every key (0.3.0)
- Name the 2026-11-29 removal date for the deprecated per-capability blocks, and document `cost_options` (0.3.0)
- Quote the /assess latency as ~10s (0.3.0)

#### [0.2.1](https://github.com/lenzhq/n8n-nodes-lenz/compare/0.2.0...0.2.1)

- Surface failure_reason, failure_class and retryable as explicit fields on a failed verification so an IF node can branch on why it stopped (0.2.1)
- Report a capacity or provider-outage 503 as transient, naming the stated wait, instead of n8n's stock "retry automatically" text (0.2.1)
- Read the API error body from where n8n actually puts it (context.data), so the 402 and 503 branches can match at all (0.2.1)
- Attach the billing and capacity wording to the caught error instead of re-wrapping it, which NodeApiError silently discarded — this is what made the 0.2.0 out-of-credits message never reach users (0.2.1)
- Carry status_code, code and retry_after on the error output so the documented Wait-node recovery has a number to read (0.2.1)
- Report a stored verification that failed as failed, instead of completed with a null verdict (0.2.1)

#### [0.2.0](https://github.com/lenzhq/n8n-nodes-lenz/compare/0.1.10...0.2.0)

- Report an out-of-credits rejection as a billing problem, not a generic API failure (0.2.0)
- Pass the original error to NodeApiError so httpCode resolves instead of always being null (0.2.0)
- Document the /extract daily cap of 1000 calls per key per day (0.2.0)
- Fix Idempotency-Key collisions when the node runs more than once in one execution, which broke Loop Over Items and AI Agent tool use with a 422 (0.2.0)
- Fail clearly when a verify submit returns no task_id instead of polling an invalid status URL (0.2.0)

#### [0.1.10](https://github.com/lenzhq/n8n-nodes-lenz/compare/0.1.9...0.1.10)

- Cover the full Lenz Public API v1 surface: batch verify, claim selection, status polling, stored-verification management, and ask history (0.1.10)
- Send an Idempotency-Key on billable POSTs so an n8n retry can no longer double-charge quota (0.1.10)
- Resolve needs-input interrupts instead of dead-ending on them (0.1.10)
- Add node version 1.1 with a Resource + Operation layout; version 1 keeps its original flat operation list (0.1.10)
