#### Unreleased

**Changes**

- **The node can read the newer shape of the Lenz API without crashing.** It still requests the older shape, so nothing changes for a workflow today: against every response recorded in that shape, the node returns exactly what 0.8.0 returned, plus one new boolean (below). For the newer shape the node reads the `failure` block (failure code, sentence, class and retryable flag), the `retry_after` wait, `completed_at` and a paused task's `claim` options, and fills the output keys it has always emitted: `failure_reason`, `failure_class`, `retryable`, `message`, `modified_at`, `claim_text`, the options' `text`, Extract's `claim` / `identified_claims` / `candidate_claims` / `locations`, and on Review Draft, Get Review, Check Citations and Get Citation Check the `failure_reason` of every failure, `summary.claim_limit_reached` / `summary.citation_limit_reached`, each assessment's `error_code`, `hint` and `identified_claims`, and a verification's `modified_at`. The newer names are kept beside them. Get Usage's per-capability blocks are not rebuilt from the newer shape. **Identical output from the two shapes is not promised in this release**; it will be when the node starts requesting the newer shape, in a later version. A request still sends a webhook URL only when one is set.
- **New, additive output field:** `not_a_claim` (boolean) on Assess and Extract results and on a failed verification: true when the answer says nothing in the input can be checked. No existing field is renamed, removed or changed.
- **`auto` is now named in the Language field.** Assess, Verify and Ask accept `auto` as the language, which answers in the language of the submitted text (on Ask, the language of the claim being discussed; on an Assess request with several claims, one language for the whole request, so enter a code for a list in mixed languages). The field was already free text and is sent exactly as typed, so nothing changes on the wire and no workflow is affected; only the field's description, the README and the workflow prompt now say it. The other operations still need a language code. Requires a Lenz API that accepts `auto`.

**Correction**

- Earlier entries (0.3.0, 0.6.0) and the README announced that the deprecated Get Usage blocks and the always-empty `candidates` / `similar_claims` keys would be removed on 2026-11-29. That date is withdrawn: the blocks and the keys are kept for existing callers.

#### [0.8.0](https://github.com/lenzhq/n8n-nodes-lenz/compare/0.7.0...0.8.0)

**New**

- **Review resource** (lenzhq/Lenz#928, #62):
  - **Review Draft** checks a whole draft (up to 50,000 characters, or one public URL): it finds the claims, quick-checks them (1 credit each), deep-checks the doubtful ones (10 credits each, 5 at Low depth) and, with **Max Citations** above 0, checks whether each cited source says what the draft attributes to it (1 credit each). Citations are checked in a pasted text only: a draft given as a URL checks none. **Suggest Edits** adds the smallest edits that make the draft say what each correction says. A review usually takes two to four minutes.
  - **Check Citations** checks only the citations, either in a text or as up to 20 statement-source pairs (URL or DOI). A source that could not be read is refunded.
  - **Get Review** and **Get Citation Check** fetch either by ID.
  - Both hand on Lenz's result plus `passed` (`outcome` is `clean`). **Wait for Completion** polls for up to **Options → Max Wait**, default **600 seconds**; a timeout returns the ID and cancels nothing. (0.8.0)
- **Lenz runs at most 3 reviews, and 3 citation checks, at once per account.** A fourth waits up to five minutes for a slot and is submitted when one opens; if none does, that item fails with a message saying so, and nothing is charged for the wait. If an item fails for good, the error names the jobs that earlier **Verify (Deep)**, **Review Draft** and **Check Citations** items in the run already started (up to 100), so their IDs are not lost when n8n drops the run's output; **Submit Batch** and **Select Claims** IDs are not included (#62) (0.8.0)

**Changes an existing workflow picks up on update**

- **No parameter or output field is renamed or removed.** A version 1.1 or 1.2 node's Resource list gains **Review**; a version 1 node is unchanged. Verify now polls through the same loop as the new operations, with the same behaviour: same retries, waits and timeout result (#62) (0.8.0)
- Some error messages are clearer:
  - A run that fails after earlier items were accepted now lists their IDs.
  - An OAuth2 credential that was never connected says to open it and click **Connect my account**, instead of n8n's "OAuth credentials not connected" / "Unable to sign without access token". With Continue On Fail, its error output now reads `error: "The Lenz OAuth2 credential is not connected yet"` with `code: "oauth_not_connected"`, so a workflow matching n8n's old text must match the new one.
  - A 409 `idempotency_conflict` says nothing new was charged and that a re-run would count as a new request; on the error output it now also carries `error_message` / `error_description` (#62) (0.8.0)

#### [0.7.0](https://github.com/lenzhq/n8n-nodes-lenz/compare/0.6.0...0.7.0)

**New**

- **Connect with your Lenz account (OAuth).** A new **Lenz OAuth2 API** credential: click **Connect my account**, sign in to Lenz and click **Allow** — no API key, client ID, secret or redirect URL to set up. n8n registers itself with Lenz the first time it connects, so any number of n8n instances and credentials can connect to the same Lenz account, each as its own connection that can be disconnected separately under **Connected apps** in Lenz. Needs **n8n 2.12.0 or later**, the first release that finds Lenz's OAuth metadata, and an OAuth Redirect URL that is a public `https://` address or `http://localhost` — a self-hosted n8n behind an internal address must set `WEBHOOK_URL` to its real address first (lenzhq/Lenz#872, lenzhq/Lenz#1172, #57) (0.7.0)
- **Account → Get Webhook Secret**, for OAuth connections: the secret Lenz signs that connection's webhook deliveries with. Lenz creates it on the first call and refuses a **Webhook URL** on an OAuth connection until then. A reconnected connection starts with no secret: run **Get Webhook Secret** again before using a Webhook URL, and check signatures with the secret it returns. An API key's secret stays on lenz.io/api-credentials (#57) (0.7.0)
- **`suggested_rewrite` on completed verifications** (Verify (Deep), Get Verify Status, Get): a rewrite of the claim that the verification's findings support, for a person to review before using it — it has not been verified itself. An empty string for a true claim, when no correction is established, and on older verifications. Same name as the API, both SDKs and the Zapier app (lenzhq/Lenz#916, #56) (0.7.0)

**Changes an existing workflow picks up on update**

- **None.** The node gains version 1.2, and only a Lenz node *added* from now on starts on OAuth. Every node already in a workflow is on version 1 or 1.1 and keeps using its API key: n8n does not save a parameter left at its default, so changing the default in place would have moved every existing node off its key, and a new node version is how that is avoided. To move an existing node to OAuth, open its credential dropdown → **Create new credential** and choose **OAuth** in the credential window: that switches the node's Authentication and connects in one step. No parameter or output field was renamed or removed (#57) (0.7.0)

**Fixes and wording**

- The Visibility, Get Many and Webhook URL descriptions spoke only of an API key; they now hold for an OAuth connection too. The README and the generated workflow prompt name the credential a new node actually asks for (#57) (0.7.0)

#### [0.6.0](https://github.com/lenzhq/n8n-nodes-lenz/compare/0.5.0...0.6.0)

**Changes an existing workflow picks up on update**

- **Max Wait (Seconds) now defaults to 300, up from 120.** A real verification finished in Lenz with a verdict, the credits were taken, and the node had already given up at 120s and returned `timeout` (lenzhq/Lenz#889). Lenz measures a standard-depth run — this node's default depth — at about 90s median with the tail past 120s. This reaches existing Verify nodes too: n8n does not save a parameter left at its default, so every node that never set Max Wait picks up 300s. Max Wait is a ceiling, not a delay, so a fast verification returns exactly as before; only the slow tail changes, from "charged, no result" to "result". The limit is per item and items run one after another, so a ten-item run can now block up to fifty minutes instead of twenty — set Max Wait explicitly under a short execution timeout (#54) (0.6.0)
- **Breaking for anyone who mapped it:** `progress` on a processing verification now forwards only `step`, `index`, `total`, `elapsed_seconds` and `poll_after_seconds`. It used to be spread through verbatim, and what came through included `content` — the accumulated evidence pool with full untruncated source quotes and every panelist's reasoning — and `step_stats`, Lenz's own per-step cost in EUR. Neither was ever part of the contract; both reached any workflow that polled mid-run. A workflow reading `progress.content` will now find it absent, which is the point (#37, #50) (0.6.0)
- Retire the `clarification_required` and `duplicate_found` pauses, which the API no longer returns to API callers: `multi_claim` is the one `needs_input` reason documented. The `candidates` and `similar_claims` keys on a `needs_input` result are deprecated: they are always empty and are planned for removal on 2026-11-29. Assess no longer reports `status: "ambiguous"`: an empty result is always `no_claim`, and its `candidate_claims` key stays (the API still sends it, always empty). No parameter was renamed or removed, so saved workflows load unchanged (#53) (0.6.0)

**Fixes**

- **A rate-limited status poll no longer abandons a verification you paid for.** The poll loop honoured a stated 429 wait with no ceiling, which held only while 429 waits were assumed to be seconds. A daily-cap 429 on the first poll slept the entire remaining Max Wait in one go, polled once at the deadline, and reported `timeout` for a verification that had finished minutes in. Now capped at 60s (#55) (0.6.0)
- **HTTP 429 has typed handling.** It arrived as n8n's stock "Request failed with status code 429", naming neither the limit nor when it clears nor that nothing was charged. The message now says all three, in minutes or hours rather than five digits of seconds (#24, #55) (0.6.0)
- **The Wait-node recovery gets a number it can use.** The error output read `retry_after`, a key a 429 does not carry, so the documented Wait-node loop was fed `undefined` on the refusal a free, daily-capped operation produces most. A short reset now arrives as `retry_after`; one too long to sit in a workflow — the `/extract` daily cap clears at midnight UTC — arrives as `resets_in_seconds` instead, so a workflow already wired to the Wait loop keeps failing fast on a daily cap rather than parking for most of a day. A 503 still always carries `retry_after` (#55) (0.6.0)
- **The recovery advice names the Wait unit.** n8n's Wait node defaults its unit to Hours, so advice reading only "set a Wait node to `{{ $json.retry_after }}`" turned a 45-second limit into a 45-hour wait. The 429 and 503 messages, the README and the workflow prompt now all say Seconds (#55) (0.6.0)
- A 429 from a CDN, WAF or proxy in front of Lenz is no longer reported as your Lenz plan being too small, with a link to billing. The error output carries `limit` and `upgrade_url` only for Lenz's own rate limit, and `upgrade_url` on an out-of-credits refusal (#55) (0.6.0)
- Read the status once more after a poll wait that was clamped to the deadline, rather than exiting the loop. A verification that completed during that final sleep came back as `timeout`, telling the caller to fetch later a verdict that was already there (#50) (0.6.0)
- Correct the paused-task lifetime, which was wrong by two orders of magnitude: a paused task stays open for **24 hours from submission**, not 10 minutes from pausing. A user who believed the old wording resubmitted — and paid again — for a Select Claims that would still have completed (#30, #50) (0.6.0)
- Honour `poll_after_seconds` when a processing response states one, instead of always returning on the node's own 2/4/8s ladder. An out-of-range value is treated as absent rather than clamped, per the API's stated guidance (#50) (0.6.0)

**Documentation**

- Explain that `verification_url` on Assess is usually empty by design: it is set only when the claim was already deep-checked with Verify and that result is one you can read (#54) (0.6.0)
- Add an **Updating** section: an installed copy does not update itself, a node added before 0.1.10 stays on node version 1, and anything new — templates especially — should use a freshly added node (#54) (0.6.0)

**Internal**

- Gate CI on test coverage, with per-file thresholds so an untested module cannot hide inside the average. The first measurement found the credential at 0%; it now has tests (#20, #52) (0.6.0)
- Stop `package-lock.json` reporting a version two releases old (#49) (0.6.0)

#### [0.5.0](https://github.com/lenzhq/n8n-nodes-lenz/compare/0.4.2...0.5.0)

- Add **Max Wait (Seconds)** to Verify (Deep), replacing the hardcoded 120s deadline. Validated and clamped to the 10-900 the widget advertises, because an expression walks straight past the widget and `usableAsTool` lets a model pass the number in directly (0.5.0)
- Stop a failed poll from losing a paid-for verification. Credits are debited when the submit is accepted, and one 502 or network blip on any of ~15 polls threw straight out of the operation carrying no `task_id` — leaving a verification that was charged for, still running, and unreachable even via Get Verify Status. Transient poll failures (5xx, 429, 408/425) are now retried inside the window, and the `task_id` rides every post-submit failure on both the error output and the thrown error (0.5.0)
- Report `passed: null` on every non-verdict terminal — timeout, `needs_input`, `failed` — so the key appears in n8n's output schema. Note that null is still falsy: an IF node reading `{{ $json.passed }}` alone routes a timeout down the false arm exactly as before, which is why the README's gate pattern now leads with `status equals completed`. A provider outage reading as a debunking was the real bug (0.5.0)
- Add `last_error` and `last_error_status` to a timeout result. A window spent entirely on failed polls used to come back as an ordinary timeout on the success path: the workflow's error branch never fired and nothing recorded that the status endpoint had never once been reached (0.5.0)
- Honour the wait a rate-limited poll states — `retry_after` or `reset_in_seconds` — instead of returning on the node's own 2/4/8s ladder, which is what tripped the limiter in the first place (0.5.0)
- Count consecutive unclassifiable poll failures rather than cumulative ones, so three unrelated blips spread across a long Max Wait, each followed by a healthy response, no longer kill a live verification (0.5.0)
- Validate Max Wait before the claim is submitted rather than at the point of use. Validated afterwards, a non-numeric expression got the claim charged and then threw an error that dropped the task id — the same lost-verification bug arriving through the front door (0.5.0)
- Fix Get Many duplicating and skipping rows when Limit is above 100: the page size shrank between pages while the server computed its window from it, so Limit 150 returned rows 51-100 twice and rows 101-150 never (#21) (0.5.0)
- Fold the request path into the Idempotency-Key, so two paused tasks offering the same claim text no longer collide on Select Claims and leave the second interrupt unresolved (#22) (0.5.0)
- Let a validation failure leave as a `NodeOperationError` instead of being re-wrapped as a `NodeApiError` with a null HTTP code — the wrong category and the wrong advice for a request that was never sent (#23) (0.5.0)
- Send an Idempotency-Key on Ask Follow-Up, so a retry replays the first answer instead of appending a second question and answer to the conversation that Get Ask History returns (0.5.0)
- Document that Extract Claims reads a public web page, or a YouTube transcript, given its URL — up to the first 50,000 characters (0.5.0)

#### [0.4.2](https://github.com/lenzhq/n8n-nodes-lenz/compare/0.4.1...0.4.2)

- Correct the low-depth price location: it lives at `cost_options.verify.depth.low`, not in `costs` under `verify_low`, which does not exist, so the documented division evaluated to NaN (0.4.2)
- Say that low depth also stops the debate after the opening arguments, so a low verdict has no rebuttal round, in every Depth description in the node and the README (0.4.2)
- Hash the node's identity into the `Idempotency-Key` instead of writing its display name into it: Node refuses a header value containing anything above U+00FF, so a node named in Cyrillic, Greek, Hebrew, Arabic or a CJK script, or with an emoji, failed every billable POST before the request left the machine — Latin-1 names such as `Prüfung` were never affected. Hashing also keeps a node named after a customer off the wire, and preferring the node id means a rename mid-execution no longer changes the key (0.4.2)
- Stop a malformed `sources` failing a verification that already completed and was paid for: a null entry now costs that one citation, and a `sources` that is not a list returns no citations rather than throwing (0.4.2)
- Refuse to push agent commits that have not been reviewed, via a `pre-push` hook enabled per clone with `git config core.hooksPath .githooks`; it has its own tests behind `npm run test:hooks` (0.4.2)
- No output field was removed or renamed. Two things changed on the wire: the `User-Agent` version, and the `Idempotency-Key` format, which is invisible to workflows but visible to anyone diffing traffic (0.4.2)
